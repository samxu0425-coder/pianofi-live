# CLAUDE.md: PianoFi Live

## Goal
Real-time version of PianoFi: audio streams in (file at real-time pace, mic, or system audio) and a piano-cover MIDI / piano roll comes out with ~1 s lag. Core engine in C++. Resume project, so every number must be real and reproducible.

## Environment
- Windows PC, PowerShell. Python 3.11+ for prototypes.
- C++17/20, CMake, MSVC (Visual Studio Build Tools).
- ONNX Runtime (prebuilt Windows release) for inference.
- miniaudio (single header) for audio I/O. Use WASAPI loopback for system-audio capture, so no virtual cable driver is needed.

## Model facts (AMT-APC, ./amt-apc, do not modify)
- Sony hFT-Transformer fine-tuned for piano covers. Weights: ./amt-apc/models/params/apc.pth
- Load: `from models import Pipeline; p = Pipeline(path_model=..., device=torch.device("cpu"))`
- Audio 16 kHz, hop 256, so 1 frame = 16 ms. Spectrogram has 256 bins.
- One pass: input [1, 256, 576] = 32 back margin + 512 frames + 32 forward margin; style vector [1, 24].
- Outputs per frame: onset, offset, frame (mpe), velocity over 88 notes.
- Max future context = 32 frames (0.512 s). That sets the lag floor.
- Style: level1/2/3 via `data.SVSampler().sample(params="levelN")`. Fix the random seed so runs are comparable.

## Layout
- RUN.md   how to run everything, in order. Read it before running anything.
- py/      stream_sim.py, export_onnx.py (writes models/), prep_audio.py, check_mel.py

- runs/    one folder per engine run: notes.csv, metrics.json, raw dumps
- test_audio/  input songs; test_audio/16k/ holds the converted 16 kHz mono copies
- results.md   every measured number, with the exact command that produced it and the machine

## How the engine works (cpp/)
- Audio thread plays the wav in 10 ms blocks at real-time speed into a ring buffer (never blocks; drops = overruns).
- Inference thread: mel frames, then frame.onnx on new frames only (h cached in a mirrored 2x512 buffer),
  then time.onnx over the latest 512 cached frames, then the streaming note decoder (port of mpe2note).
- Checks that must keep passing: pf_tests, py/check_mel.py, and at --stride 512 eval/score_engine.py
  must report array check PASSED, decoder check PASSED, F1 = 1.0000.

## Rules
- Work through RUN.md one step at a time. Stop after each step and show the output before moving on.
- If a check fails, explain the likely cause before changing any code. Never loosen a tolerance or
  skip a check to make it pass.
- Never invent or estimate a metric. If a number is not measured, write "not measured".
- Every result in results.md must be reproducible with one command.
- One task per prompt. Do not add features that were not asked for.
- Audio callback thread: no allocation, no locks, no I/O, no logging. Hand samples off through a lock-free SPSC ring buffer.
- Batch AMT-APC output (Pipeline.wav2midi) is the accuracy reference. Score with mir_eval note F1, 50 ms onset tolerance, offsets ignored.
- Keep code small and readable. Prefer the standard library.
